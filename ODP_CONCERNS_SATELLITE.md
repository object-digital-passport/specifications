# Спутник замечаний — спецификация

**Статус:** проект. Код не написан.
**Заменяет:** `chain/contracts/ODPCounterfeitConcern.sol` (108 строк).
**Основание:** находка ODP-08 аудита (`ODP_07_CONTRACT_REVIEW.md`) и решения 10, 11, 17
разбора (`ODP_REGISTRY_REDESIGN.md`).

---

## 1. Задача и границы

Учреждение публично говорит: с этим паспортом, возможно, что-то не так. Оно называет себя,
прикладывает объяснение и отвечает за свои слова своей репутацией.

**Контракт не выносит суждений.** Он не ранжирует, не считает «за» и «против», не решает,
кто прав. Он хранит датированные подписанные заявления и отдаёт их списком.

**Что заменяется и почему.** Сегодня слот один на паспорт: кто первый поставил метку, тот
один и может её снять. Самозванец, зарегистрировавшийся как `P` за стоимость газа,
не просто ставит метку — он **блокирует настоящий музей**, который после этого не может
сказать ничего (`EC(80)`). Это доказано тестом `D1`. Такая конструкция ломает саму идею
публичной сверки.

---

## 2. Правила

1. Поднимать замечание могут **только** профили `P` и `M`.
2. На один паспорт — сколько угодно замечаний от **разных** профилей.
3. От одного профиля на один паспорт — **одно действующее** замечание.
4. Снять своё замечание может **только тот профиль, который его поставил**.
   Ни автор паспорта, ни кто-либо ещё снять его не может — и это осознанно:
   заявление принадлежит тому, кто его сделал.
5. **Уровня профиля нет.** Замечание ставится только на конкретный паспорт.
   Пометить весь выпуск профиля одной транзакцией невозможно.
6. Остановленный профиль (`revokedAt != 0`) не может ни поднять, ни снять.
7. Чтение только постранично.
8. Спутник **не пишет в реестр**. Ни одной функции.

### Почему нет уровня профиля

Замечание на профиль — инструмент на порядок сильнее. Один самозванец одной транзакцией
пометил бы весь выпуск настоящего музея, включая записи, сделанные годами раньше.
Ограничить это в контракте, не начав ранжировать заявителей, невозможно.

Цена отказа измерена: одно замечание — 151 340 газа, около **$0,0011** при 30 gwei
и POL по $0,25. Пометить выпуск самозванца из 5000 паспортов по одному стоит **$5,70**
в спокойный день, $24 в загруженный. Настоящему учреждению это подъёмно. Массовая
пометка как оружие — исчезает.

---

## 3. Нейтральные названия

Оценочные слова убраны везде: из имени контракта, функций, событий и полей.

| Было | Стало | Почему старое не годится |
|---|---|---|
| `ODPCounterfeitConcern` | `ODPPassportConcerns` | «counterfeit» — приговор, а контракт приговоров не выносит |
| `raiseCounterfeitConcern` | `raiseConcern` | то же |
| `clearCounterfeitConcern` | `withdrawConcern` | «clear» значит «вопрос закрыт». Заявитель может лишь **отозвать своё**, а не закрыть вопрос |
| `CounterfeitConcernRaised` | `ConcernRaised` | то же |
| `CounterfeitConcernCleared` | `ConcernWithdrawn` | то же |
| `proverCreatorId` | `raisedBy` | «prover» обещает доказательство; здесь только заявление |
| `active` | `withdrawnAt == 0` | состояние читается из даты, а не из отдельного флага-приговора |

В интерфейсе приложения — «замечание к паспорту». Слов «подделка», «фальшивка»,
«оригинал» нет ни в одном пути.

## 4. Интерфейс

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "./ODPErrors.sol";   // error EC(uint16)

interface IODPRegistryForConcerns {
    /// @dev ПЯТЬ полей. Должно точно совпадать с CreatorRecord реестра.
    struct CreatorRecord {
        string  creatorId;
        address wallet;
        bytes1  typePrefix;
        uint256 timestamp;
        uint256 revokedAt;
    }
    function getCreatorByWallet(address wallet) external view returns (string memory);
    function getCreator(string calldata creatorId) external view returns (CreatorRecord memory);
    /// @dev Дешёвая проверка существования. Добавляется в реестр — см. §7.
    function passportExists(string calldata passportId) external view returns (bool);
}

contract ODPPassportConcerns {
    IODPRegistryForConcerns public immutable odpRegistry;

    struct Concern {
        string  raisedBy;     // creatorId профиля P или M
        bytes32 reasonHash;   // SHA-256 документа с объяснением; != 0
        string  reasonUrl;    // где лежит документ; <= 512 байт; допускается ""
        uint64  raisedAt;
        uint64  withdrawnAt;  // 0 — замечание действует
    }

    // ── Запись ───────────────────────────────────────────────────────────
    function raiseConcern(
        string calldata passportId,
        bytes32 reasonHash,
        string calldata reasonUrl
    ) external;

    function withdrawConcern(string calldata passportId) external;

    // ── Чтение ───────────────────────────────────────────────────────────
    function getConcern(string calldata passportId, string calldata raisedBy)
        external view returns (Concern memory);

    /// Все профили, когда-либо поднимавшие замечание на этот паспорт, в порядке появления.
    /// Снятые остаются в списке и читаются как снятые — история не переписывается.
    function getConcernRaisersPaged(string calldata passportId, uint256 offset, uint256 limit)
        external view returns (string[] memory raisers, uint256 total);

    /// Паспорта, на которые это учреждение поднимало замечания.
    function getConcernsByRaiserPaged(string calldata raisedBy, uint256 offset, uint256 limit)
        external view returns (string[] memory passportIds, uint256 total);

    /// Сколько замечаний действует сейчас. Счётчик, не обход списка.
    function activeConcernCount(string calldata passportId) external view returns (uint256);

    // ── События ──────────────────────────────────────────────────────────
    event ConcernRaised(
        string  indexed passportId,
        string  indexed raisedBy,
        string          passportIdText,   // строка, а не только хеш в topic
        string          raisedByText,
        bytes32         reasonHash,
        string          reasonUrl,
        uint256         timestamp
    );

    event ConcernWithdrawn(
        string  indexed passportId,
        string  indexed raisedBy,
        string          passportIdText,
        string          raisedByText,
        uint256         timestamp
    );
}
```

Строковые поля продублированы неиндексированными намеренно: `string indexed` кладёт
в topic только `keccak` строки, и восстановить её из лога нельзя. Это находка ODP-13,
и здесь она не повторяется.

## 5. Хранение

```solidity
/// keccak256(abi.encode(passportId, raisedBy)) => Concern
mapping(bytes32 => Concern) private _concern;

/// passportId => creatorId заявителей, в порядке первого появления. Никогда не сокращается.
mapping(string => string[]) private _raisersOf;

/// creatorId => passportId, на которые он заявлял. Никогда не сокращается.
mapping(string => string[]) private _raisedOn;

/// passportId => сколько замечаний действует сейчас
mapping(string => uint256) private _activeCount;
```

**`abi.encode`, а не `abi.encodePacked`.** Обе строки динамические; при `encodePacked`
пара («ODP-1», «23») и пара («ODP-12», «3») дали бы одинаковые байты. `abi.encode`
кодирует длины и делает коллизию невозможной. В сегодняшних спутниках `encodePacked`
по строкам используется и держится только на том, что идентификаторы фиксированной
длины — это хрупко, и повторять это не нужно.

**Списки не сокращаются.** Снятое замечание остаётся в `_raisersOf` и читается по
`withdrawnAt`. Так постраничное чтение устойчиво: элементы не переезжают между
страницами, пока кто-то листает.

**`_activeCount` — счётчик, а не обход.** Подсчёт действующих обходом списка стал бы
O(n) и в какой-то момент перестал бы влезать в газовый лимит вызова.

**Повторное заявление.** После снятия тот же профиль может заявить снова: запись по паре
переиспользуется, `raisedAt` и `withdrawnAt` обновляются. Полная история эпизодов живёт
в логе событий — там она неизменяема и полна. Это домашний приём ODP: сводка в хранилище,
история в логе.

## 6. Проверки и коды ошибок

Коды взяты из свободного диапазона, чтобы не пересекаться с занятыми 1–131.

### `raiseConcern`

| Проверка | Код |
|---|---|
| `reasonHash != 0` | `EC(137)` |
| `bytes(reasonUrl).length <= 512` | `EC(138)` |
| паспорт существует | `EC(136)` |
| у кошелька есть профиль | `EC(133)` |
| профиль типа `P` или `M` | `EC(134)` |
| профиль не остановлен (`revokedAt == 0`) | `EC(135)` |
| действующего замечания от этого профиля ещё нет | `EC(139)` |

### `withdrawConcern`

| Проверка | Код |
|---|---|
| у кошелька есть профиль | `EC(133)` |
| профиль не остановлен | `EC(135)` |
| действующее замечание от этого профиля есть | `EC(140)` |

Проверка `revokedAt` — это находка ODP-11: сегодня все четыре спутника объявляют
`CreatorRecord` из четырёх полей и физически не видят остановку профиля. Декодирование
при этом не падает, оно молча отбрасывает пятое поле (доказано тестом `D3`).
Здесь копия структуры содержит пять полей, и проверка стоит явно.

**Замечание на отозванный паспорт разрешено.** Отзыв — это исправление ошибки издателя,
а не приговор записи. Ограничивать здесь нечего.

## 7. Что нужно добавить в реестр

Одна функция:

```solidity
function passportExists(string calldata passportId) external view returns (bool);
```

Сегодня спутники проверяют существование паспорта, вызывая `getPassportClassification`
или `getPassportHeader` и полагаясь на их `revert`. Это заставляет спутник держать копию
большой структуры — ровно тот механизм, который породил ODP-11, и который сломается
снова, когда структура изменится.

Булев ответ снимает эту связь целиком: спутнику больше не нужно знать форму записи.

## 8. Правила приложения

Контракт не сортирует и не считает «правильные» замечания. Это делает приложение,
по своей базе проверенных профилей.

1. Имя учреждения показывать **только** для профилей из базы. Остальным — голый
   идентификатор профиля, без названия и без выделения.
2. Домен брать **из базы**, а не из цепи: вор, укравший ключ, перенаправит указатель.
3. В счётчике на карточке считать **только замечания от проверенных профилей**.
   «3 замечания» от трёх самозванцев вводят в заблуждение сильнее, чем молчание.
4. Непроверенные — под сворачивающейся строкой, без числа в бейдже.
5. Недоступный документ по `reasonUrl` — это «объяснение недоступно», а не
   «замечание необоснованно» и не «замечаний нет».
6. Снятое замечание показывать как снятое, с обеими датами. Не прятать:
   факт, что заявление было сделано и отозвано, сам по себе информативен.

## 9. Чего эта конструкция не решает

**Регистрация `P` и `M` открыта.** Любой кошелёк регистрируется как «проверяющее
учреждение» за стоимость газа. Спутник этого не чинит и не должен: открытость
задокументирована как осознанное решение. Защита — база проверенных профилей
в приложении, а не запрет в контракте.

**Замечание можно поставить массово, если не жалеть денег.** $5,70 за 5000 паспортов —
барьер для скучающего, но не для мотивированного. Ограничить это в контракте, не начав
ранжировать заявителей, нельзя.

**Хеш не делает документ доступным.** Он доказывает, что текст не подменили. Умрёт
ссылка — останется хеш и дата.

## 10. Проверить при реализации

1. Копия `CreatorRecord` — **пять** полей, и она обязана совпадать с реестром.
   Добавить тест, который падает при расхождении.
2. `abi.encode` для ключа пары. Тест на пару строк, дающих коллизию при `encodePacked`.
3. `_activeCount` сходится: поднять, снять, поднять снова, снять — счётчик обязан
   вернуться к нулю.
4. Постраничное чтение при `offset >= total` и при `limit`, выходящем за конец.
5. Замечания от двух разных профилей на один паспорт не мешают друг другу —
   это тест, который сегодня падает и ради которого всё переписывается.
6. Остановленный профиль не может ни поднять, ни снять.
7. Замер газа на первом и на повторном заявлении от одного профиля.
