# Обязательный формат `.odpass` для ODP 0.7

`.odpass` — ZIP-контейнер с расширением `.odpass`, а не отдельный формат JSON. Его корень содержит ровно четыре служебных файла с именами в нижнем регистре:

```
<любое-понятное-имя>.odpass
├── passport.json
├── generation.json
├── receipt.json
├── manifest.json
└── files/
    └── <64 lowercase hex символа SHA-256 оригинальных байтов>
```

Внешнее имя архива не определяет идентичность. Нельзя искать паспорт по случайному JSON или угадывать имена служебных файлов. В корне нет дополнительной папки-обёртки. Дубликаты ZIP-путей, абсолютные пути, `..`, символьные ссылки, шифрованные entries и вложенные архивы вместо ожидаемых payload не принимаются как структура bundle. Ограничения количества/размера/decompression ratio ещё должны быть заданы для parser до его выпуска.

| Файл | Назначение | Шаблон |
|---|---|---|
| `passport.json` | Неизменяемое полное описание | [Существующая схема](../passport-0.7.schema.json) |
| `generation.json` | Поколение, сеть, core, все спутники и deployment metadata | [Схема](generation.schema.json), [синтетический пример](examples/generation.json) |
| `receipt.json` | Связь описания с фактическим выпуском | [Схема](receipt.schema.json), [синтетический пример](examples/receipt.json) |
| `manifest.json` | Перечень файлов и их точные hashes/размеры | [Схема](manifest.schema.json), [синтетический пример](examples/manifest.json) |

Все JSON — UTF-8 без BOM, строгий JSON без повторяющихся ключей. `passport.json` хранится в нормативной канонической форме SPEC §10 с `passportId: null`. Его hash не включает другие служебные файлы. Остальные JSON не изменяют обязательство паспорта, но требуют собственной проверки согласованности и доверия. Точные формы заданы схемами, неизвестные поля в трёх новых служебных JSON отвергаются.

Адреса в новых служебных файлах — полные lowercase `0x` + 40 hex символов. chainId/blockNumber/byteLength — десятичные строки, чтобы не терять точность между платформами. Идентификатор generation отличается от версии `0.7`; одинаковый version byte не разрешает подменять ABI или deployment.

## Проверки сверх JSON Schema

- Receipt содержит operationId успешного задания mint, сверяемый с событием и getMintOperation.
- Receipt и generation имеют одинаковые generationId/chainId/registry; chain record соответствует receipt, включая blockHash. Сам receipt не доказывает подлинность цепи.
- Каждый из девяти известных satellite roles ровно один раз присутствует либо в satellites, либо в absentSatelliteRoles. Дубликаты/пересечение/пропуск запрещены. Отсутствующий edition satellite недопустим для паспорта с соответствующим anchor.
- Deployment identities сверяются с независимо доверенным фиксированным manifest поколения. Нельзя доверять фиктивному deployment только потому, что его JSON структурно валиден.
- Путь каждого payload равен `files/` + hash без префикса; hash и byteLength пересчитываются по распакованным байтам. Повтор path запрещён; один оригинал может обслуживать несколько ссылок на тот же hash.
- Набор обязательных payload следует из passport/profile, а не из редактируемого флага в manifest. Все оригинальные фото/цифровые файлы и нужные данные тиража должны быть сохранены. Неполный архив отображается как неполный, не как успешно проверенный полный .odpass.
- Canonical JSON и исходные файлы не переписываются при переносе на другой сайт. Внешние URLs можно распространить отдельно; они не заменяют содержимое files/.

## Статус

Реализован `chain/tools/bundle.mjs`: проверка уже распакованных entries, строгого JSON, канонического паспорта, связей generation/receipt/edition, полного списка ролей, оригинальных payload и независимо переданного manifest поколения. Возвращает раздельные результаты; receipt сам по себе не подтверждает цепь. Дерево тиража проверяется по полному address list. Импортёр/экспортёр ZIP с ограничениями распаковки и подключение к приложению ещё не реализованы. API entries нельзя напрямую использовать как безопасный ZIP importer. NFC исключён из текущего этапа. Где хранить и как раздавать готовый .odpass — отдельный открытый вопрос.

**Все адреса, hashes и блоки в examples вымышлены.** Это примеры формы, не утверждённое поколение и не полный выданный bundle; `files/` с оригиналами здесь отсутствует. `0.7-local-fixture` не используется для реального выпуска.
