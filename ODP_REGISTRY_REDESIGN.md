# Реестр ODP — переработка ядра

**Статус:** проект решения. Код не написан, ничего не развёрнуто.
**Основание:** аудит на коммите `d9e656ee5039d97d66fc7fe6df601fc9c7534960`
(`ODP_07_CONTRACT_REVIEW.md`, 36 находок, 36 исполняемых PoC) плюс разбор модели
с владельцем проекта 15 сентября 2026.

**Ключевой факт, который делает переработку дешёвой:** контракт 0.7 **ещё не развёрнут**.
SPEC §868 фиксирует, что таблица канонических адресов пуста. Значит миграции нет,
брошенных записей нет, второго поколения нет. Цена переработки — только время разработки.

---

## 1. Что изменилось в постановке

Три решения владельца переопределили задачу. Всё остальное — следствия.

**1. Паспорт — это факт регистрации в момент выпуска. И всё.**
Ни владельца, ни передачи, ни получателя. Реестр не утверждает, чья вещь, — он
утверждает, что такие-то байты были зарегистрированы таким-то профилем тогда-то.

**2. Отзыв — это исправление собственной ошибки.**
Не средство против подделки и не средство против кражи ключа. Отсюда окно в 72 часа.

**3. Развиваться будут спутники, а не реестр.**
`v1 → v1.1` — новый спутник и новые правила в SPEC, тот же реестр по тому же адресу.
Новый контракт нужен только на `v1 → v2`. Основание — SPEC §2025 и §2028.

Следствие третьего пункта: **всё, что может жить в спутнике, должно жить в спутнике.**
В реестре остаётся только то, что физически не может быть вынесено.

---

## 2. Физическая граница

Спутник — отдельный контракт со своим адресом и своим хранилищем. Он **читает** реестр.
Он **не пишет** в реестр.

Отсюда правило, которое и определяет состав ядра:

> В реестре обязано остаться всё, что меняет саму запись паспорта. Всё остальное — вне.

Сегодня это правило нарушено: спутник тиражей имеет два входа в реестр
(`mintUnitPassport`, `lockEditionRevocation`). Из этого исключения выросли два
критических пункта аудита. После переработки правило становится безусловным:
**реестр не вызывает ни один спутник и не принимает вызовов ни от одного спутника.**

## 3. Журнал решений

| # | Решение | Что из него следует |
|---|---|---|
| 1 | Владельца и передачи нет | Удаляются `owner`, `initialOwner`, `transferPassport`, `PassportTransferred` |
| 2 | Событий паспорта в реестре нет | Удаляются `recordPassportEvent`, `PassportEventRecorded` и счётчики событий. Историю пишут P и M в своих спутниках |
| 3 | Отзыв — 72 часа от выпуска, только выпустивший | `governance` теряет отзыв. После 72 часов не может никто |
| 4 | Связи с ошибочным паспортом нет | Поля «заменяет» нет. Ошибочная запись остаётся как есть |
| 5 | Юнит-паспортов нет | Удаляется `mintUnitPassport`. Остаётся только активация кода |
| 6 | `lockEditionRevocation` удаляется | Окно закрывают часы, а не активация |
| 7 | Подтверждение агента переносится в реестр | Спутник связей больше не нужен |
| 8 | Адрес файла выносится в спутник | Запись паспорта становится полностью неизменяемой |
| 9 | Роутер расширений не разворачивается | Подстановка `tx.origin` удаляется вместе с ним |
| 10 | Замечания — только P и M, сколько угодно на паспорт | Отдельный спутник, монополия на слот снимается |
| 11 | Оценочных слов нет нигде | Ни «подделка», ни «оригинал» — ни в коде, ни в интерфейсе |
| 12 | Имени организации в цепи нет | Домен — в спутнике-справочнике, имя — в файле на домене, «проверено» — в базе приложения |
| 13 | Список поколений — в SPEC и на GitHub | Указателя в цепи нет: он вернул бы привилегированный ключ |
| 14 | `freeze()` удаляется | Вместе с ним уходят `frozen` и `deployer`. В реестре не остаётся **ни одного** привилегированного адреса |
| 15 | Месячные лимиты — без изменений | C — 1000, B — 100 000, P и M без ограничений. Принято как есть |
| 16 | Линия остаётся 0.7 | Нумерация обсуждается с сообществом отдельно |
| 17 | Замечаний на профиль **нет** | Только на паспорт. Массовая пометка одной транзакцией невозможна |
| 18 | Истории вещи в реестре нет — сознательно | Переезды, повреждения, реставрация живут в экспертизах P и M |

## 4. Новый реестр

### 4.1 Хранение

```solidity
struct CreatorRecord {
    string  creatorId;     // "C-482-930-174-005"
    address wallet;
    bytes1  typePrefix;    // C / B / P / M
    uint256 timestamp;
    uint256 revokedAt;     // 0 = активен
}

struct Passport {
    string  passportId;
    uint8   contractVersion;
    address creator;        // кошелёк-издатель, неизменен
    string  creatorId;
    uint32  year;
    uint8   month;
    // карточка — неизменяема после выпуска
    string  title;              // 1..128 байт
    string  authorName;         // 1..128 байт
    string  shortDescription;   // 1..256 байт
    string  domain;             // <=128 байт
    string  objectType;         // physical / digital / mixed
    uint8   contentClass;
    uint8   lifecycleStatus;    // ставится при выпуске и больше не меняется
    uint8   aiStatus;
    uint8   verificationMethod;
    uint8   editionModel;
    // обязательства по содержимому — неизменяемы
    bytes32 dataHash;
    bytes32 anchorsHash;
    uint32  anchorTypesMask;
    bytes32 imageHash;
    bytes32 fileHash;
    uint256 timestamp;          // момент выпуска; от него считается окно отзыва
    // единственное изменяемое поле во всей записи
    bool    revoked;
    uint256 revokedAt;
    bytes32 revocationReasonHash;
    address mintAgent;          // address(0), если выпускал сам принципал
}
```

**Исчезли:** `owner`, `dataUrl`, `imageUrl`, `eventCount`, `lastEventKind`, `lastEventAt`.

`dataUrl` и `imageUrl` переезжают в спутник хостинга (§5.5). В цепи остаются только хеши —
то, что действительно неизменяемо.

### 4.2 Внешняя поверхность

```solidity
// ── Профили ──────────────────────────────────────────────────────────────

function getCreator(string calldata creatorId) external view returns (CreatorRecord memory);
function getCreatorByWallet(address wallet) external view returns (string memory);

// ── Агент выпуска (перенесено из спутника связей) ────────────────────────
function requestMintAgentRole(string calldata principalCreatorId) external;
function confirmMintAgentRole(address agent) external;   // подтверждает сам принципал

// ── Выпуск ───────────────────────────────────────────────────────────────
function mintPhysical(PassportMintInputs calldata m, string calldata onBehalfOf)
    external returns (string memory passportId);
function mintDigital(...) external returns (string memory);
function mintMixed(...)   external returns (string memory);

// ── Отзыв: 72 часа, только издатель ──────────────────────────────────────
function revokePassport(string calldata passportId, bytes32 reasonHash) external;

// ── Чтение ───────────────────────────────────────────────────────────────
function getPassportHeader(string calldata passportId)         external view returns (...);

    external view returns (string[] memory, uint256);

/// Дешёвая проверка существования — чтобы спутникам не приходилось держать копию
/// структуры записи и полагаться на revert. Снимает целый класс ODP-11.
function passportExists(string calldata passportId) external view returns (bool);
```

Из тупла выпуска исчезают `initialOwner`, `dataUrl`, `imageUrl`; из сигнатур —
параметр `dataUrlIsFolderBase`.

### 4.3 Окно отзыва

```solidity
uint256 internal constant REVOCATION_WINDOW = 72 hours;

function revokePassport(string calldata passportId, bytes32 reasonHash) external {
    Passport storage p = _passports[passportId];
    if (p.creator == address(0))            revert EC(12);   // нет такой записи
    if (p.revoked)                          revert EC(18);   // уже отозван
    if (msg.sender != p.creator)            revert EC(17);   // только издатель
    if (_creators[p.creatorId].revokedAt != 0) revert EC(131); // профиль остановлен
    if (block.timestamp > p.timestamp + REVOCATION_WINDOW) revert EC(132); // окно закрыто
    if (reasonHash == bytes32(0))           revert EC(16);
    ...
}
```

Пять проверок, каждая по своей причине:

- `governance` в списке нет — у него больше нет этого права;
- проверка `revokedAt` закрывает находку ODP-05: остановленный профиль теряет отзыв
  вместе с выпуском, и вор может дотянуться максимум до записей последних 72 часов;
- окно считается от `p.timestamp`, то есть от блока выпуска, и не требует внешнего вызова.

`passportIdText` закрывает находку ODP-13: сегодня идентификатор лежит в topic только
хешем, и восстановить его из квитанции невозможно. Неиндексированная строка стоит
около 8 газа за байт и снимает задачу целиком.

**Удалены:** `PassportTransferred`, `PassportUrlsUpdated`, `PassportEventRecorded`.

### 4.5 Чего в реестре больше нет вообще

| Что удалено | Какие находки аудита умирают вместе с ним |
|---|---|
| `extensionRouter` и подстановка `tx.origin` | **ODP-01** (критическая) |
| `mintUnitPassport` | **ODP-02**, **ODP-04** (критическая и высокая) |
| `lockEditionRevocation`, `_revocationLocked`, `editionUnits` | **ODP-03** (критическая), ODP-12 |
| `governance` и три сеттера спутников | **ODP-29** (критическая), ODP-15, ODP-16 |
| `owner`, `transferPassport`, `initialOwner` | ODP-06, ODP-14, часть ODP-13 |
| `recordPassportEvent` | часть ODP-06 |
| `dataUrl` / `imageUrl` в записи | ODP-22, ODP-23, ODP-25 |
| `freeze()`, `frozen`, `deployer` | ODP-16, ODP-24 |
| `relationsSatellite` (перенесён внутрь) | ODP-29 |

Из 36 находок аудита **удалением закрывается 16, включая все четыре критические.**
Остальные — правки спутников, SPEC и клиента.

### 4.6 В реестре не остаётся привилегированных адресов

`governance` удалён — его три сеттера стали бессмысленными после решений 5, 6, 7 и 9:
спутников, которые реестр вызывает, не осталось. `freeze()` и `deployer` удалены решением 14.
Конструктор становится пустым: записывать в него нечего.

Значит после развёртывания **не существует адреса, который может сделать с реестром
хоть что-нибудь особенное.** Ни остановить, ни отозвать чужую запись, ни переключить
спутник — спутников реестр вообще не знает.

Заголовок контракта сегодня утверждает «No owner. No admin. No pause function.
No selfdestruct.» Аудит отметил это как неправду (ODP-24). После переработки
утверждение становится верным — не правкой комментария, а правкой кода.

**Цена, прямо.** Аварийного выключателя нет. Если после развёртывания найдётся дефект,
остановить реестр в цепи будет нельзя: записи продолжат накапливаться.

Остаётся только внешняя остановка — список поколений в SPEC и на GitHub (решение 13):
клиенты перестают признавать адрес, и новые записи в нём теряют смысл. Уже сделанные
записи при этом остаются читаемыми навсегда.

Этот размен осмыслен ровно потому, что ядро стало маленьким: профили, выпуск, отзыв
в 72 часа. Чем меньше кода, тем меньше вероятность дефекта, который потребовал бы
выключателя.

## 5. Спутники

Ни один не имеет права записи в реестр. Все только читают.

| Спутник | Состояние | Что делает |
|---|---|---|
| **5.1 Тиражи** | правится | `openEdition` + `activate`. Юнит-паспортов и замка отзыва нет |
| **5.2 Замечания** | переписывается | P и M, сколько угодно на паспорт, плюс уровень профиля |
| **5.3 Экспертизы** | правится | Добавить проверку `revokedAt`; сюда же переезжает история вещи |
| **5.4 Авторский ключ** | правится | Только `creator` — владельца больше нет (закрывает ODP-14) |
| **5.5 Хостинг** | **новый** | `passportId → dataUrl, imageUrl`. Пишет издатель или его агент |
| **5.6 Справочник профилей** | **новый** | `creatorId → domain`. Пишет только кошелёк самого профиля |
| **5.7 Якоря файлов** | без изменений | Как сейчас |

Во всех спутниках копия `CreatorRecord` расширяется до пяти полей и добавляется
проверка `revokedAt` — это находка ODP-11.

### 5.2 Замечания — требования

- Поднимать могут **только** профили `P` и `M`.
- Хранение по паре «паспорт + профиль»: много учреждений на один паспорт, много
  паспортов на одно учреждение. Монополии на слот нет (закрывает ODP-08).
- **Уровня профиля нет.** Замечание ставится только на конкретный паспорт. Одной
  транзакцией пометить весь выпуск профиля невозможно — это убирает оружие массовой пометки.
  Цена для настоящего музея: 151 340 газа за замечание, то есть около **$0,0011**;
  пометить выпуск самозванца из 5000 паспортов стоит **$5,70** в спокойный день.
- **К `reasonHash` добавляется `reasonUrl`.** Сегодня в спутнике есть только хеш причины,
  и указать, где лежит объяснение, негде. Текст живёт вне цепи, хеш связывает его с записью.
- Снять своё замечание может только тот, кто его поставил.
- Чтение постранично.
- Названия нейтральные: «замечание к паспорту». Слова «подделка» нет.
- Порядок и счётчики — забота приложения, по его базе проверенных профилей.
  Контракт не ранжирует и не оценивает.

### 5.6 Как собирается имя организации

1. Из цепи: `creatorId → domain` (спутник-справочник).
2. С домена: `/.well-known/odp.json`, где лежит имя. Подтверждается контролем домена.
3. В приложении: база проверенных профилей — `creatorId + chainId + адрес реестра + ожидаемый домен`.

Домен приложение берёт **из своей базы**, а не из цепи: иначе вор, укравший ключ,
перенаправит указатель, и проверка «пройдёт».

## 6. Регистрация кода юнита — как устроено

**Подготовка (бренд, офлайн, один раз на тираж):**

1. Мастер-ключ ≥ 256 бит, CSPRNG, машина без сети.
2. Секрет юнита: `HKDF-SHA256(мастер, контекст тиража ‖ uint32be(номер))`.
3. Печатаемый код: первые **100 бит**, 20 символов Crockford Base32 + 5 контрольных.
4. Закрытый ключ: `SHA-256("ODP-UNIT-KEY-v1" ‖ код ‖ контекст тиража)`.
5. Лист дерева: `SHA-256(uint32be(номер) ‖ адрес)`. Узлы — `SHA-256(левый ‖ правый)`.
6. В цепь — **только корень**, 32 байта на весь тираж. Список адресов публикуется на домене.

**Регистрация (покупатель, на телефоне):**

1. Нормализация кода: верхний регистр, убрать дефисы, `O`→`0`, `I`/`L`→`1`.
2. Проверка 5 контрольных символов. Опечатка отсеивается 1 к 33 млн, **до сети**.
3. Вывод ключа и адреса из кода.
4. **Бесплатно, офлайн:** доказательство по списку адресов против корня в цепи.
5. **Бесплатно, одно чтение:** был ли номер зарегистрирован раньше.
6. Подпись: `"ODP-UNIT-ACTIVATE-v1" ‖ chainId ‖ адрес спутника ‖ id тиража ‖ номер`.
7. Отправка. Кто отправил — не записывается и не проверяется.

**Энтропия (SPEC §20.6).** Порог `80 + ceil(log2(unitCount))` бит, никогда ниже 80.
Кодировка несёт 100. Для тиража 5000 требуется 93 — запас в 128 раз.
Порог **на цель**: атакующему годится любой код, поэтому работа делится на размер тиража.
При 5000 юнитов это порядка 2⁸⁸ операций, каждая — хеш плюс операция на кривой.

**Чего схема не закрывает, прямо:**

1. Бренд знает все ключи и может зарегистрировать бутылки сам.
2. Скопированный код ловится только со второго раза; первая жертва не узнаёт ничего.
3. Кто видел код до продажи — склад, типография — может его зарегистрировать.

## 7. Деньги

Измерено локально, на конфигурации будущего развёртывания.

| Операция | Газ | При 30 gwei / $0,25 | При 80 gwei / $0,40 |
|---|---:|---:|---:|
| Регистрация профиля | 171 878 | $0,0013 | $0,0055 |
| Выпуск паспорта | 642 752 | $0,0048 | $0,0206 |
| Открыть тираж на 5000 | 123 537 | $0,0009 | $0,0040 |
| Активация одного юнита | 63 486 | $0,0005 | $0,0020 |

**Бесплатно и навсегда:** чтение любой записи; проверка принадлежности кода к тиражу
(офлайн); проверка, был ли код зарегистрирован раньше.

**Платно:** только добавление записи.

Тираж 5000 бутылок: $0,006 вперёд плюс $0,0005 за каждую реально проверенную бутылку.
Если активируют все — **$2,40**. Для сравнения, 5000 отдельных паспортов стоили бы $24.

**Кто платит за покупателя.** Функция активации не смотрит на отправителя, поэтому
подпись можно передать обычным HTTP-запросом тому, кто её отправит и заплатит.
Покупателю не нужны ни кошелёк, ни криптовалюта, ни регистрация.

**Это не централизация, и вот проверка по трём признакам:**

1. Отправитель не может соврать — что записано, определяет подпись, которой у него нет.
2. Не может заблокировать — функция открыта всем, отправит другой или сам владелец кошелька.
3. Без него работает всё главное — чтение, проверка кода и проверка повторного
   использования бесплатны и не требуют его вообще.

Это та же граница, которую SPEC §397 уже провёл для файла на домене организации:
вспомогательный механизм, от которого не зависит ни один результат проверки.

## 8. Как P и M объясняют, что не так

Хеш в цепи связывает объяснение с записью. Сам текст живёт вне цепи.

| Где | Что есть сегодня | Что надо |
|---|---|---|
| Экспертиза (`submitProof`) | `documentHash` + `documentUrl` | ничего, механизм готов |
| Замечание | **только** `reasonHash` | добавить `reasonUrl` |

То есть учреждение публикует документ у себя, кладёт в цепь его SHA-256 и ссылку.
Любой читатель скачивает документ, считает хеш и убеждается, что текст не подменили
после того, как замечание было поставлено.

**Ограничение, которое надо назвать вслух.** Хеш доказывает, что текст не менялся.
Он **не** делает текст доступным. Если ссылка умрёт, останется только хеш и факт
«замечание было поставлено тогда-то». Это та же граница, что и у файла паспорта.

Отсюда правило приложения: недоступное объяснение — это «объяснение недоступно»,
а не «замечание необоснованно» и не «замечания нет».
