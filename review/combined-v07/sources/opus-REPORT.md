# REPORT — независимый аудит ODP 0.7 (0.7-redesign-4)

Вердикт относится к снимку `sha256(snapshot.sha256) = 27d10023eaed987feb50e1ef9e947d44b32d82d1d639bc8a8d128c82414bd0fb`
и bytecode ядра runtime `0x4d915a931254b3b4e01fc4657278a875a03ef50ca9200ab30714f0322f79901c` (см. SCOPE.md).
Это не внешний профессиональный аудит.

## Итоговый статус

| К чему | Статус |
|---|---|
| Архитектура | **Готова при условиях**: решения A2 (права после компрометации/stop), A3 (идемпотентность журнала), A4 (носитель) |
| Bytecode этих хешей | **Готов при условиях**: критических ошибок кода не найдено; но A1 (процедура сборки/deploy) и A6 (внешнее ревью) обязательны. При изменениях по A2–A5 вердикт на новые хеши не переносится |
| Публичный выпуск | **Не готов**: нет приложения/importer/chain evidence, deploy-скрипт может выкатить непроверенный bytecode, носитель не выбран |

## Самые важные подтверждённые проблемы

1. **F-01 (High):** `deploy.js` развёртывает содержимое `artifacts/` после incremental-сборки. Воспроизведено: исходники
   байт-в-байт равны проверенным, а развёрнут другой runtime ядра (`0x5fa62bb9…` вместо `0x4d915a93…`); manifest
   этого не показывает, `sourceDirty` не блокирует. Причина — viaIR-bytecode зависит от AST ID всего compiler input (F-09).
2. **F-02 (Medium):** при краже ключа владелец выбирает между «остановить выпуск» и «отозвать поддельные паспорта» —
   сделать оба нельзя. После stop вор сохраняет право необратимо снять все прежние заявления/экспертизы/замечания,
   а владелец теряет канал коррекции. SPEC §17 описывает ущерб от компрометации неполно.
3. **F-03 (Medium):** у `publishStatement`/`submitProof` нет operationId: повтор после таймаута создаёт дубли Active записей.
4. **F-04 (Medium):** payload активации/этикетки и формат кода зашиты в bytecode, хотя формат носителя ещё не выбран.

Необходимые решения до deployment: A1–A5 в RELEASE_GATES.md.

## Архитектурная оценка

Минимальное неизменяемое ядро без администратора, без callback и с отдельными спутниками — **реально реализовано**
и соответствует цели «запись обязательств, которую никто не может переписать». Основные гарантии держатся
в коде, а не в NatSpec: неизменяемость карточки, 72 ч, operationId, commitment тиража, одноразовые слоты.
Главные слабые места лежат **на границах**: процедура сборки/deploy, модель ключей (нет ротации, stop работает
как «мёртвая рука» без различения владельца и вора), и перенос большой части смысла (доверие к поколению,
идентичность, проверка payload, ZIP, свежесть) в приложение, которого нет.

## Угроза / компромисс / невыполнимое обещание

- **Угроза:** F-01 (оператор выкатит непроверенный код), F-02 (кража ключа), F-03 (дубли при повторе).
- **Сознательный компромисс:** самообъявленные P/M и Sybil (F-12), нет ротации ключа, 72 ч, hosting-заморозка,
  тираж навсегда привязан к одному спутнику, stop между mint и open навсегда блокирует тираж.
- **Обещание, которое продукт сам по себе выполнить не может:** «переносимый проверяемый паспорт без доверия к серверу» —
  пока нет ZIP importer, доверенного встроенного manifest и проверки chain evidence. NatSpec «скомпрометированный
  кошелёк не подделает второй сигнал» (F-07) — сформулировано сильнее, чем обеспечено.

## Долгосрочные сценарии

| Сценарий | Сохраняется | Нельзя проверить | Теряется необратимо |
|---|---|---|---|
| Сайт/issuer исчез | Карточка, хеши, статусы в цепи; активации | Файлы, если нет архива; личность issuer | Возможность обновить hosting, коррекции, открыть неоткрытые тиражи |
| Архив потерян, есть только QR | ID → карточка из цепи (при известном поколении) | Фото/оригиналы, anchors (только хеши), edition proofs | Содержимое passport.json, если нет других копий |
| Полный архив без сети | Целостность bytes, совпадение внутр. хешей | Что паспорт вообще в цепи, отзывы, активации (только кэш с блоком/временем) | — (до появления сети) |
| Клиент не знает спутник | Ядро | Все заявления/тиражи этого спутника → «unsupported» | — |
| Ошибка в неизменяемом спутнике | Данные ядра; старые записи спутника | Корректность затронутой функции | Существующие тиражи нельзя перенести; нужен новый namespace |
| Новое поколение / смена политики доверия | Старые адреса и история (если клиент их хранит) | Автоматическая связь старого и нового | Непрерывность ID: ID не глобальны между registry |
| Кража ключа issuer | Старые записи ядра | Какие действия после кражи сделал владелец | Active-статус старых заявлений (F-02) |

## Подтверждено / опровергнуто

Подтверждено: 88 + 8 тестов, vectors, tsc, ABI/TypeChain воспроизводимы, EIP-170 (ядро 12129 байт), 32 детекта Slither
с корректным разбором (weak-prng — ID, без вектора; strict equality — ложные), npm audit 11 low (dev-цепочка),
отсутствие рекурсии в Yul, неприменимость advisories 0.8.20, выполнимость тиража 2^20 (4,3 мин, 2,4 ГБ), газ ≤1,03 M.
Опровергнуто/уточнено: «отличался только creation bytecode»; «deploy-процедура защищает от неверной сборки»;
«компрометация не может менять старые записи» (записи — да, их действующий статус — нет).

## Пределы

Нет fuzzing-движков и формальной верификации, нет проверки приложения, реальной сети и печати.
Property-проверки — seeded. Независимость ограничена (см. SCOPE.md). Отсутствие критических находок в коде не доказывает отсутствие ошибок.
