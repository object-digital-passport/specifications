# Этап 3: проверка содержимого переносимого паспорта

Реализовано в `chain/tools/bundle.mjs`, функция `validateBundleEntries`.
Это проверка массива `{name, bytes}` после безопасного чтения контейнера.
Сам ZIP parser и exporter пока отсутствуют. Solidity и ABI этапа 2 не изменялись.

Проверяется:
- точные имена, отсутствие лишних/повторных путей;
- строгий UTF-8 JSON без BOM и повторных ключей, схемы, каноничность passport;
- единые generation/chain/registry, полное разбиение восьми ролей, разные адреса;
- соответствие namespace тиража manifest поколения;
- hash, размер и путь каждого оригинала, отсутствие незаявленных payload;
- обязательные фото, digital file и публичный address list по самому паспорту;
- точное совпадение с independently pinned generation, если передано вызывающим кодом.

Отчёт не имеет общего зелёного «паспорт подлинный»: целостность, наличие файлов,
поколение, цепь, личность, свежесть истории и доказательства тиража разделены.
Совпадение hash address list пока не подтверждает его формат или Merkle root.
Проверка edition proofs и физической подлинности сообщает unsupported.
Для неизвестных anchors отдельной проверки их обещаний пока нет.

## Проверка

`cd chain && npm run test:tools` — 8 passing; сохранён `bundle-tests.log`.
Сценарии включают удаление оригинала вместе с записью manifest, подмену namespace,
фиктивное поколение, повреждённый JSON/UTF-8, несоответствие hashes/размеров,
дубликаты ролей/адресов/путей и запрет выдавать offline integrity за chain trust.
