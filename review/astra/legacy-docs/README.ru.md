## Что это?

**Object Digital Passport (ODP)** даёт физическому или цифровому объекту паспорт, который доказывает три вещи:

1. **Когда** объект был зарегистрирован — метка времени блокчейна, которую нельзя подделать задним числом;
2. **Кто** его зарегистрировал — публичный ID профиля, который можно сверить с официальным сайтом издателя;
3. **Что описание с тех пор не менялось** — криптографические отпечатки каждого фото, размера и отличительной особенности.

Без компании-посредника. Без подписки. Проверка **всегда бесплатна** и будет работать и через 50, и через 100, и через 250 лет — потому что реестр живёт в публичном блокчейне (Polygon), а не на чьём-то сервере. **Что это обещание значит:** развёрнутый реестр отвечает столько, сколько живёт сеть. **Чего оно не значит:** что один адрес обслуживает все поколения — каждая линия `v0.x` это отдельный реестр, и паспорта между ними не мигрируют, поэтому паспорт вечно проверяется против *своей* линии (SPEC.md §7). Регистрация стоит только сетевую комиссию (~$0.01–0.03). Сам протокол не берёт **ничего и никогда**. Всё под лицензией MIT.

**Цель: сделать подделку истории объекта максимально трудной — за копейки.**

> ⚠️ **Статус Alpha:** контракт ещё может меняться между версиями 0.x, что может затронуть ранние паспорта и аккаунты. Для долгосрочного использования дождитесь стабильной версии — цель: **январь 2027**.

## Как это работает — простыми словами

При регистрации вы получаете **публичный ID профиля** (вида `C-482-930-174-005`). Вы публикуете его на своём сайте или в соцсетях — так люди понимают, что ID действительно ваш. Это не пожелание: на этом держится вся модель доверия.

Оформляя паспорт объекта, вы описываете его так, как музеи и полиция описывают вещи для опознания (принцип [Object ID](https://icom.museum/en/resources/standards-guidelines/objectid/)): фотографии, размеры, материалы и **отличительные особенности**, которые подделывателю не скопировать — тот самый отреставрированный разрыв, та пометка мелом на подрамнике. Начиная с v0.6:

- небольшая читаемая **карточка** (название, автор, краткое описание) лежит прямо в блокчейне — объект понятен даже без файла;
- все идентификационные факты собраны в одном блоке **`anchors[]`** с отпечатком в блокчейне — и без жёсткого минимума (фото + размеры + материалы + отличительные особенности) паспорт *вообще не выпустится*;
- история объекта **только дописывается**: продажи, повреждения, реставрации — это события, которые можно добавить, но нельзя переписать.

Полное описание живёт в переносимом файле **`.odpass`**, который вы храните и передаёте; блокчейн хранит его отпечатки. Измените одну запятую — отпечаток перестанет совпадать, и это увидит любой проверяющий.

При проверке объекта страница показывает **уровень защиты** с одного взгляда — **базовый** (минимум опознания сходится), **с пломбой** (＋защитная или NFC-пломба), **с подтверждением** (＋за объект поручилась институция). Он пересчитывается на лету из блокчейна при каждой проверке, а не печатается наклейкой — поэтому не устаревает и его нельзя нарисовать.

ODP — инструмент в руках человека, а не волшебная палочка: он делает подделку дорогой и заметной и даёт экспертам, покупателям и институциям одни и те же защищённые от подмены факты.

### Что на самом деле делает проверка

```mermaid
flowchart LR
    ID["Passport ID<br/>(QR, NFC или вручную)"] --> CHAIN["Читаем реестр<br/>карточка · хэши · события"]
    CHAIN -->|не найден| INVALID(["INVALID"])
    CHAIN --> FETCH["Скачиваем файл .odpass<br/>по публичной ссылке"]
    FETCH -->|недоступен| UNVER(["UNVERIFIABLE<br/>регистрация всё равно доказана"])
    FETCH --> HASH["Пересчитываем SHA-256<br/>документ · якоря · карточка"]
    HASH -->|есть расхождение| TAMPER(["TAMPERED"])
    HASH -->|всё сошлось| OK(["AUTHENTIC<br/>+ уровень защиты"])
```

Каждый шаг — только чтение и бесплатно: без кошелька, без аккаунта, без разрешения от нас. Полный алгоритм — [`SPEC.md` §11](SPEC.md).

## Как это устроено внутри

Реестр намеренно разделён. Ethereum ограничивает контракт 24 КБ, поэтому ядро остаётся маленьким, а всё необязательное живёт в **спутниках** — отдельных контрактах, которые читают основной реестр, но могут быть добавлены позже без его передеплоя и без переноса чьих-либо паспортов.

```mermaid
flowchart TB
    subgraph core["Ядро — сами паспорта"]
        REG["ObjectDigitalPassport<br/><i>реестр: карточка, хэши, события</i>"]
        LIB["ODPPassportLib<br/><i>линкуемая библиотека проверок</i>"]
    end
    subgraph sat["Спутники — опциональные, добавляются со временем"]
        PROOF["ODPPassportProofRegistry<br/><i>институциональные подтверждения</i>"]
        REL["ODPRegistryRelations<br/><i>делегирование, аффилиация</i>"]
        CF["ODPCounterfeitConcern<br/><i>флаги подделки</i>"]
        DOC["ODPWalletDocumentAnchor<br/><i>якорение хэшей файлов</i>"]
        EXT["ODPExtensionMintRouter<br/><i>минт через расширения</i>"]
    end
    ISSUER(["Автор · Бренд · Институция"]) -->|регистрация, минт| REG
    REG -.->|delegatecall| LIB
    PROOF & REL & CF & DOC & EXT -.->|чтение| REG
    VERIFIER(["Любой проверяющий"]) -->|только чтение| REG
    VERIFIER -->|только чтение| PROOF & CF
```

Актуальные адреса — [`docs/GUIDE.md` → Current Release](docs/GUIDE.md#current-release).

## Запустить у себя

Интерфейс — обычный статический HTML, без сборки и серверного фреймворка:

```bash
git clone https://github.com/object-digital-passport/object-digital-passport.github.io.git
cd object-digital-passport.github.io
TMP=$(mktemp -d) && cp -r frontend/. "$TMP/" && cp -r backend "$TMP/backend" && cd "$TMP"
python3 -m http.server 8000    # затем откройте http://localhost:8000/verify.html
```

Если интересуют контракты:

```bash
cd chain/deploy && npm ci && npm test
```

## Для кого это?

| Префикс | Тип аккаунта | Кто |
|---|---|---|
| **C** | Автор | Художники, фотографы, мастера |
| **B** | Бренд | Студии и бренды, выпускающие продукцию (повышенные лимиты) |
| **P** | Проверяющая институция | Галереи, аукционные дома, экспертные организации |

Префикс типа — сам по себе первый маркер проверки: «музейный» аккаунт, оформляющий паспорт на новую работу живого художника, — ваш первый красный флаг 🚩

## Вопросы и ответы

**Зачем мне это?**
Защитить свои работы от подделок — и собрать «неразрушимый» каталог сделанного, с доказательством «когда».

**Нужно ли разбираться в крипте?**
Только основы: поставить кошелёк, сохранить фразу восстановления, пополнить на пару долларов POL. Заведите отдельный кошелёк под ODP — не тот, где сбережения.

**Что будет, если сайт проекта исчезнет?**
Паспорта переживут его. Реестр — в публичном блокчейне, код — под MIT: любой может поднять свой верификатор. В этой независимости весь смысл.

**Можно ли потом отредактировать паспорт?**
Ядро — никогда. Именно поэтому ему можно верить. То, что меняется со временем (владелец, состояние, местонахождение), записывается **событиями**: только новые записи, никаких переписываний. Опечатка в ядре = отзыв паспорта и выпуск нового.

**Сколько это стоит?**
~$0.01–0.03 сетевой комиссии Polygon за регистрацию или паспорт. Проверка бесплатна. Сам стандарт комиссию не берёт — принципиально и навсегда.

**Где техническая часть?**
Начните с [**вики**](https://github.com/object-digital-passport/specifications/wiki/Home-ru) — там всё человеческим языком, — а затем нормативная база: [`SPEC.md`](SPEC.md) (англ.; [русский перевод](docs/ru/SPEC.md) обновляется до v0.6).
