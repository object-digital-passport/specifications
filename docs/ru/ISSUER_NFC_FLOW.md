# Порядок работы эмитента с NFC — сканировать чип до минта

*Перевод справочно. Нормативный оригинал — только на английском: [`docs/ISSUER_NFC_FLOW.md`](../ISSUER_NFC_FLOW.md). Этот текст может содержать ошибки; при расхождении верен английский.*

Это **обязательный порядок минта** для физических паспортов с пломбой NTAG 424 DNA TagTamper в ODP v0.5.

## Почему порядок важен

Минт до сканирования чипа позволяет опубликовать неверные `nfcPublicKey` или `uid` в `passport.json` и в цепи. Более позднее прикладывание чипа не исправит неверный якорь в реестре без выпуска нового паспорта.

## Правильный порядок

```text
1. Инициализация метки
      → ODP Android Companion: Provision new NTAG 424 tag (только заводским ключом)
      → либо NXP TagWriter / инструменты для ПК
      → даёт 16-байтовый ключ приложения EV2 (nfcPublicKey) + UID
      → публикуемый ключ ОБЯЗАН быть 01h..04h, никогда не 00h — см. SPEC §6, шаг 1
2. Веб ODP — passport.html
      → вставить ключ EV2
      → сканирование Android-компаньоном в режиме эмитента
      → импорт JSON настройки чипа (фиксирует UID + ключ)
3. Заполнить форму паспорта + изображения/файлы
4. Заминтить в цепи
5. Записать NDEF-носитель (URI odp://, по SPEC §12.2 — без имени хоста) — после того, как ID паспорта существует
6. Заблокировать файл носителя: условия доступа Write и ReadWrite выставить в Fh
```

## Веб ODP (passport.html)

В секции NFC:

1. Вставьте **ключ приложения EV2** из инициализации (32 hex-знака). Это ОБЯЗАН быть
   немастер-ключ — `01h`..`04h`. Ключ `00h` — это AppMasterKey, и он даёт право на `ChangeKey`
   над каждым ключом метки; опубликовав его в паспорте, вы позволяете любому читателю
   перевыпустить ключи настоящей пломбы и запереть её владельца снаружи. `00h` держите у себя,
   публикуйте другой.
2. Нажмите **Scan chip with Android companion** (в handoff входит `route.mintPageUrl` для возврата).
3. После сканирования нажмите **Open mint page in browser** в результате компаньона (сценарий Pixel / один телефон) либо **Copy chip setup JSON** и вставьте в **Import chip setup**.
4. Chrome возвращается на `passport.html?chipSetup=…` — UID и `nfcPublicKey` подставляются сами; параметр запроса из адреса вычищается.
5. Подключите кошелёк (WalletConnect на мобильном) и нажмите **Mint Passport** — до подтверждения настройки чипа кнопка заблокирована.

## Android-компаньон (режим эмитента)

Handoff из веба использует `route.intent = issuer-chip-setup`.

Приложение:

- выполняет **симметричный challenge-response EV2** ключом из веба,
- читает **аутентифицированный UID**,
- для моделей TagTamper читает **GetTTStatus** (обязано быть **INTACT**),
- выгружает JSON `odp-chip-issuer-setup` для импорта в веб,
- при заданном `route.mintPageUrl` предлагает **Open mint page in browser** с `?chipSetup=<base64url(json)>`.

NDEF-носитель на этом сканировании **не** требуется: метка может быть пустой до того, как на неё записан адрес Verify.

## Цикл на одном телефоне (Pixel)

```text
Chrome (passport.html) → диплинк в компаньон → прикладывание NFC → Open mint page in browser
      → Chrome (та же passport.html + chipSetup) → WalletConnect → Mint
```

Отдавайте `passport.html` со стабильного HTTPS- или LAN-адреса, доступного с телефона (не только `file://`), чтобы `mintPageUrl` из handoff был достижим при возврате из компаньона.

## Формат выгрузки

```json
{
  "type": "odp-chip-issuer-setup",
  "version": 1,
  "chip": {
    "uid": "0x04a1b2c3d4e5f6",
    "model": "NTAG424DNA_TAGTAMPER",
    "publicKey": "0x00112233445566778899aabbccddeeff",
    "ev2AuthPassed": true,
    "tamperState": "intact"
  }
}
```

Импорт в веб требует `ev2AuthPassed: true`, а для TagTamper — ещё и `tamperState: intact`.

## После минта

1. Соберите `.odpass` / разместите JSON паспорта.
2. Сгенерируйте полезную нагрузку **odpOffline** / NDPP в **Manage passport** и заякорите `ndppCommitmentHash` в цепи, если пользуетесь профилем носителя NDPP.
3. Запишите NFC-носитель с финальным адресом Verify и офлайн-нагрузкой (операторская запись компаньоном из Android-handoff либо TagWriter с выгруженным файлом `.ndef`).
4. При операторской записи компаньоном с handoff, содержащим `write.offlinePayloadBase64`, приложение **блокирует** файлы NTAG `01h` (CC) и `02h` (NDEF) после успешной записи: чтение остаётся свободным (`Eh`), запись, чтение-запись и смена запрещены (`Fh`). Это соответствует рекомендации NXP менять доступ на запись NDEF после персонализации.
5. По желанию: пересканируйте в режиме **verify**, чтобы подтвердить пломбу высокого уровня доверия.

**Честное ограничение:** блокировка требует второго прикладывания тем же ключом EV2. Раскладки NDEF с включённым SDM приходится доводить в инструментах NXP. Поля паспорта в цепи остаются неизменяемыми независимо от блокировки метки.

См. также [ANDROID_NTAG424DNA_TAGTAMPER.md](ANDROID_NTAG424DNA_TAGTAMPER.md) и SPEC.md §6 / уровень 2A.
